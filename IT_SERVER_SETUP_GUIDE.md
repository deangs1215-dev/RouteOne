## Overview

RouteOne is a Node.js + React field sales CRM that reads from SYSPRO and serves sales reps via mobile and web browsers. It runs as a Windows Service on your test server (`routeone-test.sbakels.net` / `192.168.0.22`).

### Current Environment
- **OS:** Windows Server (2019 or later)
- **Location:** `C:\RouteOne`

- **Repository connection:** Mapped Z: drive to laptop `C:\Projects\RouteOne`

2. **NSSM 2.24** — Already installed at `C:\nssm\nssm-2.24\win64\nssm.exe`
3. **Git** (for deployments) — Already configured

## Running as a Windows Service (NSSM)

### Service Name
**RouteOne** (check status via Services.msc or PowerShell)

### Service Commands
```powershell
# Check status
C:\nssm\nssm-2.24\win64\nssm.exe status RouteOne

# Restart service
C:\nssm\nssm-2.24\win64\nssm.exe restart RouteOne

# Stop service
C:\nssm\nssm-2.24\win64\nssm.exe stop RouteOne

# Start service
C:\nssm\nssm-2.24\win64\nssm.exe start RouteOne
```

### Service Configuration (NSSM Details)
- **App:** `C:\nodejs\node.exe` (or wherever Node.js is installed)
- **App Parameters:** `C:\RouteOne\server/index.js`
- **Startup Directory:** `C:\RouteOne`
- **Log File:** `C:\RouteOne\server\logs\service.log`
- **Log Append:** Yes (rotates at 10MB)
- **Restart:** Auto-restarts on crash (restart delay: 0 seconds)
- **Survives:** RDP logoff and server reboots

### Service Startup Flow
1. NSSM starts `node.exe` with `server/index.js`
2. Node reads `.env` file for configuration
3. Connects to SQLite database at `C:\RouteOne\server\data\fieldsales.db`
4. Starts Express server on port 4200 (HTTP) and 4443 (HTTPS — when configured)
5. Logs startup messages to `service.log`

## Configuration File (.env)

### Location
`C:\RouteOne\.env` (on server only — never committed to Git)

### Required Settings
```env
# Security — MUST be present
SECRET_KEY=<32-char random hex string>

# Server origins (comma-separated, hostname first)
APP_ORIGIN=http://routeone-test.sbakels.net:4200,http://192.168.0.22:4200

# Database location
DATABASE_URL=C:\RouteOne\server\data\fieldsales.db

# Backup directory

# SYSPRO integration (SQL Server)
SYSPRO_HOST=<IP or hostname>
SYSPRO_PORT=1433
SYSPRO_DB=<database name>
SYSPRO_USER=<read-only SQL login>
SYSPRO_PASSWORD=<encrypted password>

# Email (M365/SMTP for order notifications, password reset links)
SMTP_HOST=smtp.office365.com
SMTP_USER=<M365 account>
SMTP_PASSWORD=<M365 password>

# Optional: HTTP-only testing (temporary, must be removed for production)
COOKIE_SECURE=0  # Allows cookies over HTTP; REMOVE when HTTPS is live
```

### Editing `.env` Safely
**Never use Notepad** — it will silently overwrite the file. Instead, use this PowerShell helper:

```powershell
function Set-EnvValue($Path, $Key, $Value) {
    $lines = @(Get-Content $Path -ErrorAction SilentlyContinue)
    $pattern = "^$([regex]::Escape($Key))="
    if ($lines -match $pattern) {
        $lines = $lines | ForEach-Object { if ($_ -match $pattern) { "$Key=$Value" } else { $_ } }
    } else {
        $lines += "$Key=$Value"
    }
    Set-Content -Path $Path -Value $lines -Encoding UTF8
}

# Example: update SYSPRO password
Set-EnvValue "C:\RouteOne\.env" "SYSPRO_PASSWORD" "NewPasswordHere"

# Verify
Get-Content "C:\RouteOne\.env" | Select-String "SYSPRO"
```

## Code Deployment Workflow

### Overview
Code changes are made on the laptop (`C:\Projects\RouteOne`), deployed to the server via a mapped Z: drive, and the service is restarted.

### Deployment Process

**Step 1: On the laptop, run the deployment script**
```powershell
cd C:\Projects\RouteOne
.\deploy.bat
```

This script:
- Builds the React frontend (`npm run build`)
- Compiles TypeScript (if present)
- Uses `robocopy` to sync source to `Z:\` (mapped to server's `C:\RouteOne`)
- **Excludes** (never overwrites on server):
  - `.env` and `.env.*`
  - `server/data/` (live database)
  - `server/backups/` (backup snapshots)
  - `server/uploads/` (customer photos/documents)
  - `node_modules/` (will be reinstalled on server)
  - `.git/` (code history stays local)

**Step 2: On the server (via RDP), restart the service**
```powershell
C:\nssm\nssm-2.24\win64\nssm.exe restart RouteOne
```

The restart process:
1. Stops the current Node process
2. Runs `npm install` (installs/updates dependencies)
3. Runs `npm run build` (builds the backend & frontend)
4. Starts Node again with the new code

**Step 3: Verify deployment**
```powershell
# Check that the service is running
C:\nssm\nssm-2.24\win64\nssm.exe status RouteOne

# Check for errors in the service log
Get-Content "C:\RouteOne\server\logs\service-error.log" -Tail 30

# Test the health endpoint from any machine
curl http://routeone-test.sbakels.net:4200/api/health
```

2. Copy backup file to `C:\RouteOne\server\data\fieldsales.db`
3. Restart service: `nssm start RouteOne`

## Integration with SYSPRO

### SQL Connection
The app reads from SYSPRO via read-only SQL views. Configuration:
- **Host/Port/Database:** Configured in `.env`
- **Login:** Separate read-only SQL account (recommended — currently may be using developer credentials)
- **Views Used:**
  - `vw_FS_Customers` — customer list
  - `vw_FS_Products` — product catalog
  - `vw_FS_Stock` — warehouse inventory
  - `vw_FS_CustomerPricing_ContractBuyingGroup` — pricing (~13M rows, sync-intensive)
  - `vw_FS_Invoices` — invoice history
  - `vw_FS_RepSalesByMonth` — sales rep targets

### Data Sync
- **Triggered via:** Integration page in the app UI (or via cron scheduler, configurable per entity)
- **Behavior:** Reads from SYSPRO views, updates local SQLite tables
- **Frequency:** Configurable per entity (off/hourly/4-hourly/daily)
- **Important:** The `customer_pricing` sync reads 13M+ rows and blocks the entire Node process during execution. **Keep it set to "Off (manual only)"** until re-architected.

## Security & Access Control

### Authentication
- **Method:** JWT (JSON Web Tokens) in HttpOnly cookies
- **Duration:** 12-hour session (auto-refresh on activity)
- **Password Policy:** 12+ characters, no common patterns
- **Forced Password Change:** Users marked `must_change_password=1` are forced to change on next login

### User Roles
- **Admin/Manager:** Access to settings, user management, orders, reports
- **Rep:** Mobile sales rep (read-only for most data, can create orders/quotes/visits)
- **Customer Portal:** Limited customer (view own invoices, quotes)

### Network Security
- **Internal VPN only** (not internet-facing)
- **RDP access:** Restrict to admin users
- **Database:** Accessible only from the Node process (SQLite — no separate SQL daemon)

## Performance Tuning & Limits

### Current Constraints
- **SQLite max concurrent connections:** 1 (by design — suitable for small teams, < 50 concurrent users)
- **Sync operation:** Blocks the server for 5–20 minutes during large syncs (e.g., customer_pricing at 13M rows)
- **Database file:** Stored on application disk (C:\); should be moved to a separate protected volume at production scale
- **Disk usage:** 1.15 GB database + 6 GB backups (at 14-day retention) — growing. Monitor disk space; alert if < 50GB free.

## Known Issues & Workarounds (2026-08-12)

### 1. Login Freeze (FIXED)
**Issue:** Users logged in, page appeared to load, then bounced back to login screen.  
**Root Cause:** Session cookies set to `Secure`, but served over HTTP — browsers drop them silently.  
**Workaround:** Added `COOKIE_SECURE=0` to `.env` (temporary, for testing). Must be removed when HTTPS is live.

### 2. GPS Location Pickup (BLOCKED ON HTTPS)
**Issue:** Reps report "can't pick up my location" in the mobile app.  
**Root Cause:** Browsers block `navigator.geolocation` on non-HTTPS origins (except `localhost`).  
**Resolution:** Will be fixed when HTTPS (port 4443) is implemented.

### 3. Customer Pricing Sync Blocks Server
**Issue:** Syncing the `customer_pricing` entity from SYSPRO (~13M rows) locks up the entire app for 5–20 minutes.  
**Root Cause:** Single synchronous SQLite transaction on the main Node thread.  
**Workaround:** Keep entity set to "Off (manual only)" in Integration settings. Do not put on an automatic schedule.
